SECURITY / TRANSPARENCY

Security, built to be inspected.

A practical overview of what Luna Guard checks, where its boundaries are, and how local data is handled. Details reflect the current desktop implementation and may change between releases.

01

DETECTION

Detection Architecture

Desktop scans run on demand. The pipeline uses local SHA-256, SHA-1 and MD5 lookups, configured YARA rules, file context (including entropy and bounded PE metadata when supported), and selected threat-feed indicators. Quick scan can also inspect selected process and memory/system signals. Each result includes evidence; risk scores are heuristic summaries, not probabilities.

02

EXTERNAL INDICATORS

Threat Intelligence

Feed updates contact MalwareBazaar (including its recent detections feed), ThreatFox and URLhaus. File contents and scan history are not uploaded to those providers. The optional abuse.ch API key is stored locally and protected with Windows DPAPI for the current account; this does not protect against malware already running as that user. Network access is used when updating feeds.

03

BOUNDED EXTRACTION

Archive Protection

Archive scanning applies limits across nested members. Content that is encrypted, corrupt, unsupported, inaccessible, or over budget can be skipped and must leave the scan marked incomplete.

Deep archive mode stops when the temporary drive cannot retain 1 GiB free. Full C: scanning has no overall file-count or time cap, does not follow junctions/reparse points, and reports skipped paths as incomplete. ZIP central-directory memory is proportional to its capped member count.

04

INTEGRITY CHECKS

Quarantine Security

Quarantine records metadata before copying, verifies SHA-256 before removing the source, and writes state changes atomically. Restore verifies the digest, refuses destination conflicts, and uses a temporary file followed by atomic no-overwrite placement. Startup recovery leaves ambiguous operations in a recovery-required state. Permanent deletion requires an explicit UI confirmation and another digest check.

05

LOCAL BY DEFAULT

Privacy

Desktop scans are local. Scan history is stored locally and may contain file paths and detection reasons; activity logs are held in process memory. A bounded audit log records allowlisted event metadata and IDs, not paths or API keys. The desktop dashboard API binds to loopback and uses a per-run token plus Host/Origin checks. Mobile scans only files selected by the user and does not inspect other apps’ private data.

06

SCOPE AND CAVEATS

Limitations

  • Luna Guard is an on-demand scanner and quarantine helper, not real-time protection or a replacement for Microsoft Defender.
  • A clean result covers only components the scan could inspect. Permission errors, unsupported files, and resource limits make results incomplete.
  • YARA rules are first-party heuristics; licensing and independent review may be incomplete. Review matches for false positives.
  • PE signature presence checks metadata only; it does not validate Authenticode signatures or publisher trust. Version strings can be forged.
  • Risk scores are heuristic summaries, not calibrated probabilities. The Windows executable is unsigned and may show an unknown-publisher or SmartScreen warning.
07

RESPONSIBLE REPORTING

Security Disclosure

Report suspected vulnerabilities through the repository owner’s GitHub security reporting channel when enabled, or contact the maintainer privately before publishing exploit details. Do not include API keys, personal file contents, or signing material.
